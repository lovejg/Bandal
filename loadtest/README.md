# 부하 테스트

Phase 4 측정용. 설계는 `docs/DECISIONS.md`의 ADR-074(무엇을 어떻게 재나), ADR-075(관측 묶음).

- 부하를 받는 쪽: 테스트 서버 `bandal-loadtest`. 운영과 같은 모양(A1 2 OCPU/12GB)과 같은 이미지 태그. `deploy/loadtest/`로 띄운다.
- 부하를 거는 쪽: 운영 서버의 k6(Docker, CPU 1개). 같은 데이터센터 안의 사설 IP로 건다.
- 숫자: k6 요약(사용자 쪽 p95/p99, 에러율)과 Grafana "Bandal 한눈에"의 환경 `loadtest`(서버 쪽 원인 숫자).

## 파일

| 파일 | 하는 일 |
|---|---|
| `seed.sql` | 측정용 데이터. 큰 학교(연세대 신촌) 사용자 2,000, 모집중 300, 지난 방 3,000. 작은 학교(광운대) 200, 20, 200. 나머지 11곳 30, 5, 50 |
| `seed.sh` | 테스트 서버에서 `seed.sql`을 넣고 방 목록 캐시를 비운다. 운영 서버에서는 멈춘다 |
| `k6/bandal.js` | 시나리오 A(한 방에 몰림), B(목록 새로고침), C(둘을 같이) |

## 순서

1. 측정마다 데이터를 새로 넣는다(`seed.sh`, 1초). 같은 데이터에서 시작해야 전후를 비교할 수 있다. 핫한 방 id는 늘 4126이다.
2. k6를 돌린다. 예:
   - `SCENARIO=A JOINERS=40 HOT_ROOM=4126`
   - `SCENARIO=B` (큰 학교 최대 200명, 작은 학교 40명, 단계마다 1분)
   - `SCENARIO=C HOT_ROOM=4126 JOINERS=200 BG_VUS=100`
3. 결과 JSON과 Grafana 화면 캡처를 남긴다. 숫자는 ADR과 JOURNAL에 적는다.

액세스 토큰이 15분짜리라 한 번의 실행은 15분 안에 끝나야 한다.
